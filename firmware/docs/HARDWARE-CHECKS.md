# First assembled-device checks

**Pending.** No firmware has been flashed and no sensor, USB, button, sleep-current, RTC-retention or battery-discharge test has been performed for v0.1.0. Software build/test results are separate in [validation.json](validation.json).

Start these when Erez connects the prototype and authorises flashing. Save serial output, board/sensor versions, battery voltage, firmware commit and observations with the results. The bare SCD30 prototype uses the same protocol as the Adafruit SCD30 breakout.

1. **Bench boot:** upload `feather-debug`; observe one boot summary without waiting for a serial monitor. Check SCD30 `0x61`, TSL2591 `0x29`, DS3231 `0x68` and MAX17048 `0x36`. Confirm actual TFT rotation, button labels, numeric formatting and USB recovery. Verify the soldered bare-module connection against the module pinout before powering it.
2. **No missing-data substitutions:** disconnect/reconnect a sensor while power is off, reboot, and confirm a missing-sensor message, null API values and blank CSV columns. Cover the light aperture, test a bright source, and check gain changes and saturation handling. Compare light readings to the library example if gain behaviour is questionable.
3. **Phone connection:** D1 opens a unique `Sensor-xxxxxx` network with a unique password. Scan the TFT QR on iOS and Android. Confirm the quiet zone is unobstructed, manual credentials work and the browser page loads without internet. Test ordinary browsers as well as captive-portal windows. Test CSV downloads to a phone.
4. **Clock backup:** with a fresh RTC coin cell, set time from the phone. Disconnect USB and the main cell, wait, reconnect and confirm valid increasing UTC without a browser. Repeat reset/watchdog/brownout recovery as appropriate. With an unset/removed backup cell, confirm that the next cold boot does not invent a date. Check the phone sync event retains the previous UTC in the CSV.
5. **Recording:** use 5 s, 60 s and a long interval; confirm one sample per due slot with real sensor values, channel masks and settings revisions. Change phone time forward/back and confirm log scheduling remains monotonic while timestamps show the correction. Confirm the first two minutes after sensor power-up are marked as warming. Check a long-interval wake reads the sensor before going back to sleep.
6. **Controls:** D0 cycles pages; holding it sleeps after release. D1 opens/closes Wi-Fi. D2 starts/pauses. From sleep, D0/D2 wake without accidentally pausing/starting, and D1 wakes into the hotspot. Verify all three wake sources independently, short presses, held buttons and release debounce.
7. **Calibration:** first exercise start, cancel, timeout and invalid-reference rejection without applying a correction. Confirm the six-minute countdown restarts after a CO₂ interruption and the whole session ends within 20 minutes. Only apply FRC beside a trusted stable reference. Read back the correction, check its audit event, and confirm records during stabilisation have the `Calibrating` flag. Verify ASC stays off unless explicitly enabled.
8. **Deep sleep:** upload `feather`, unplug USB, and verify screen/radio/NeoPixel are off while logging. Confirm GPIO7 stays high and SCD30 remains continuously powered across timer wakes; verify no restart/reset command or rail glitch. When paused or storage is full/faulted, verify the external rail is off during sleep and the RTC survives on its coin cell. USB disappearing in deep sleep is expected.
9. **Concurrent work:** while logging at 5 s, download a near-full CSV and raw file over a slow connection. Check timestamps for missed slots, memory stability, Wi-Fi timeout and responsiveness. Streaming services sensors and the logging loop between chunks, but synchronous network writes can delay a sample; it must never create fabricated catch-up records.
10. **Storage/recovery:** export known data before testing interruption. Test a normal reset, power loss during append, partial tail and corrupt interior record. Check valid prefix retention and `recovered_bytes`; an interior error must stop writes rather than erase. Verify LittleFS's on-device truncate path and formatting an entirely blank partition. A nonblank mount failure must preserve contents until explicit ERASE. Raw-file export is unavailable if the filesystem itself cannot mount; take a full flash backup before erasing in that case.
11. **Full/erase/update:** fill storage, confirm stop-on-full and unchanged earlier data. Check ERASE fails while logging or without exact confirmation. Export, pause and erase; verify settings and RTC remain. Upload the same firmware layout and confirm stored data survives. Test a missing/bad filesystem without automatic destructive recovery.
12. **Power and thermal:** profile the states in [POWER.md](POWER.md) when convenient. Check battery percentage/voltage against a meter, USB/battery transitions, charging, brownout handling, and full discharge duration. Allow at least ten minutes for thermal stabilisation in the enclosure before determining a temperature offset. Use actual in-enclosure reference measurements; firmware cannot cancel arbitrary solar or electronics heating.

Cross-platform upload/recovery on Windows and Linux, long-duration endurance and class-set hardware variation remain workshop acceptance tasks after the Mac prototype succeeds.
